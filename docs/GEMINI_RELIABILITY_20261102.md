## 本轮改动

### 等响应头不再拖到全局 600 秒

针对 Gemini 的 OpenAI 兼容转发：

| 显式思考等级 | 单次等响应头 | 同一请求跨账号累计预算 |
| --- | --- | --- |
| low / medium 等 | 60 秒 | 90 秒 |
| high | 90 秒 | 120 秒 |

- 高思考工具调用曾有合法超过一分钟的首包，单独保留更长但有界的预算；不降级实际 reasoning。
- 计时器在收到响应头时撤销，不对正常 SSE 生成过程套同一个总超时。
- Gemini Chat 最多初始一次加两次换号，不按原先 50 次扫池。
- 网关自身响应头超时仅对该账号的目标模型退避 5 分钟，不禁用账号、凭证或其他模型；纯累计预算耗尽不惩罚尚未请求的账号。
- Google 明确 high-demand 的 503 模型冷却从 30 秒调整为 2 分钟；其他平台不变。
- Chat、Responses→Chat、Messages→Chat 使用同一等待封装；原生 Gemini CLI/generateContent 路径不在本轮改动范围。

### 取消与真实上游状态分开

- Deva 等客户端主动取消时，Chat 入口记录本地 499 / client_canceled，不再补写 502，不因取消更新账号健康状态。
- 网关等待超时可向客户端返回 504 / upstream_timeout，但标明 LocalTimeout；不填写伪造的 Google HTTP 504。已有真实上游 503 仍保留在各次 attempt 中。

### 跨天签名与原账号路由一起保留

- 签名 TTL 从 6h 调整为 14 天，成功恢复时刷新 TTL。
- 上游确实返回并已保存签名时，将相应 Gemini 粘性账号路由续期到相同期限；恢复签名时也刷新路由，避免账号路由一小时后先过期。
- 路由种子在模型映射前生成，保持与调度器一致；仍按原组调度，账号健康校验与模型冷却继续优先，不强行使用不健康原账号。
- 超过单次 128 个恢复候选时优先最新工具历史，而非只查最旧的 128 个。
- 保留 tenant / group / account / credential / model / session / tool ID / name / arguments 的隔离，不跨账号借用签名。
- 对 Google 官方 Chat 入口的 Gemini 3/4，仅检查最后一个用户回合中的工具调用：当前必要真实签名恢复不了时，直接返回明确的 `400 gemini_tool_signature_unavailable`，不反复换号。旧用户回合历史和合法并行工具的无签名后续项不误拦。
- 旧版已过期/已丢失签名无法反算，必须开始新的用户回合或新会话；延长 TTL 只保护此后真实保留的数据，不伪造或填 dummy。
